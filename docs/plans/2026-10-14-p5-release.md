# P5 Performance Gate and Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove the B1–B9 targets with benchmarks, then package releases for GitHub, Docker (GHCR), npm and PyPI, with docs. Publishing itself waits for the owner.

**Architecture:** `bench/` holds harness programs and Go benchmarks; CI compares against `bench/baseline.txt` with `benchstat`. GoReleaser OSS builds binaries, checksums, SBOM, cosign signatures and two Docker images. npm and PyPI packages are generated from GoReleaser artifacts by our own scripts.

**Tech Stack:** Go benchmarks (`b.Loop`), `golang.org/x/perf/cmd/benchstat`, GoReleaser OSS, cosign, Syft, `simonw/go-to-wheel` (or equivalent per-platform wheel builder), Node 22 for the npm launcher.

**Spec:** [architecture §8](2026-10-14-architecture.md), [performance §8–§10](../../research/performance.md).

## Global Constraints

- Targets exactly as architecture §8. A missed target blocks the release; record the measured value and the fix attempted.
- Build flags: `CGO_ENABLED=0 -trimpath -ldflags="-s -w -X .../internal/version.Version={{.Version}}"`. No UPX, no GOAMD64 > v1, no PGO before a real CPU profile exists.
- Platforms: linux/amd64, linux/arm64, darwin/amd64, darwin/arm64, windows/amd64, windows/arm64.
- npm: launcher package + one package per platform with `os`/`cpu` fields, no postinstall (Biome pattern). PyPI: one wheel per platform.
- Docker: `ghcr.io/<owner>/<name>:<ver>` RPC-only from `scratch` (+ CA certs); `:<ver>-browser` from `chromedp/headless-shell`.
- ⛔ Owner gate before: making the repo public, creating any registry package, pushing any tag that triggers publishing.

## Review Focus

1. npm install on an unsupported platform → clear error naming supported platforms. Test in Task 3.
2. Windows path with spaces for the PyPI wrapper → binary found and exec'd. Test in Task 4.
3. Docker RPC-only image with no keyring → key-file fallback works with a mounted config volume. Test in Task 2.
4. Benchmark noise on CI runners → compare with benchstat at p < 0.05 over 10 runs; fail only on significant regressions > 10%. Test in Task 1.
5. Client negotiating protocol `2026-07-28` → server answers correctly on stdio. Test in Task 1.
